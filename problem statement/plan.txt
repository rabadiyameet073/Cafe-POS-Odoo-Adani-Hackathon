🎯 Project Overview
Odoo Cafe POS is a comprehensive Restaurant Point of Sale system with:

Multi-role access (Customer, Cashier, Kitchen Staff, Admin)
Table-based ordering with floor management
Real-time kitchen display system
Multiple payment methods (Cash, Net Banking, UPI QR)
Customer order tracking
Feedback system
Comprehensive reporting dashboard

User Flows
Customer Flow:

Login → View Available Tables (Floor-wise) → Select Table → Browse Menu → Add to Cart → Place Order → Select Payment Method → Pay → Track Order Status → Submit Feedback

Cashier Flow:

Login → Open POS Session → View All Customer Orders → Process Walk-in Orders → Manage Payments → View Dashboard → Close Session

Kitchen Staff Flow:

Login → View Kitchen Display → Update Order Status (To Cook → Preparing → Completed) → Mark Items Ready

Admin Flow:

Login → Configure Products → Manage Floors & Tables → Setup Payment Methods → View Reports → Export Data

### **1. Authentication System**

**Pseudocode - Backend (authController.js)**
FUNCTION signup(request, response):
GET email, password, full_name, phone, role FROM request.body
IF user with email EXISTS in users table:
    RETURN error "User already exists"

hashed_password = HASH password using bcrypt

new_user = INSERT INTO users (email, password_hash, full_name, phone, role)

jwt_token = GENERATE JWT with payload {user_id, email, role}

RETURN response with {user_data, token}
FUNCTION login(request, response):
GET email, password FROM request.body
user = SELECT FROM users WHERE email = email AND is_active = true

IF user NOT FOUND:
    RETURN error "Invalid credentials"

is_valid = COMPARE password with user.password_hash using bcrypt

IF NOT is_valid:
    RETURN error "Invalid credentials"

jwt_token = GENERATE JWT with payload {user_id, email, role}

RETURN response with {user_data, token}

**Pseudocode - Frontend (authService.js)**
FUNCTION signup(userData):
response = POST request to "/api/auth/signup" with userData
IF response successful:
    STORE token in localStorage
    SET user in AuthContext
    REDIRECT to appropriate dashboard based on role
ELSE:
    SHOW error toast
FUNCTION login(credentials):
response = POST request to "/api/auth/login" with credentials
IF response successful:
    STORE token in localStorage
    SET user in AuthContext
    
    IF role is "customer":
        REDIRECT to "/customer/floors"
    ELSE IF role is "cashier":
        REDIRECT to "/cashier/dashboard"
    ELSE IF role is "kitchen":
        REDIRECT to "/kitchen/display"
    ELSE IF role is "admin":
        REDIRECT to "/admin/dashboard"
ELSE:
    SHOW error toast

### **2. Customer Floor & Table Selection**

**Pseudocode - Backend (floorController.js, tableController.js)**
FUNCTION getAllFloors(request, response):
floors = SELECT * FROM floors WHERE is_active = true ORDER BY display_order
FOR EACH floor IN floors:
    floor.tables_count = COUNT tables WHERE floor_id = floor.id AND is_active = true

RETURN response with floors
FUNCTION getTablesByFloor(request, response):
floor_id = GET from request.params
tables = SELECT * FROM tables 
         WHERE floor_id = floor_id 
         AND is_active = true 
         ORDER BY table_number

FOR EACH table IN tables:
    // Check if table has active order
    active_order = SELECT FROM orders 
                   WHERE table_id = table.id 
                   AND status NOT IN ('completed', 'cancelled')
    
    IF active_order EXISTS:
        table.status = "occupied"
    ELSE:
        table.status = "available"

RETURN response with tables

**Pseudocode - Frontend (FloorSelectionPage.jsx)**

    ELSE:
        SHOW grid of table cards with status colors

### **3. Customer Menu & Cart**

**Pseudocode - Backend (productController.js, orderController.js)**
FUNCTION getAllProducts(request, response):
products = SELECT p.*, c.name as category_name
FROM products p
JOIN product_categories c ON p.category_id = c.id
WHERE p.is_active = true AND p.is_available = true
ORDER BY c.display_order, p.name
FOR EACH product IN products:
    product.variants = SELECT * FROM product_variants 
                      WHERE product_id = product.id 
                      AND is_active = true

RETURN response with products
FUNCTION addOrderItem(request, response):
GET order_id, product_id, variant_id, quantity, notes FROM request.body
// Verify order belongs to current user
order = SELECT FROM orders WHERE id = order_id AND customer_id = current_user_id

IF NOT order:
    RETURN error "Order not found"

// Get product details
product = SELECT FROM products WHERE id = product_id
variant = SELECT FROM product_variants WHERE id = variant_id (if provided)

// Calculate prices
unit_price = product.price
variant_price = variant ? variant.extra_price : 0
line_total = (unit_price + variant_price) * quantity
tax_amount = line_total * (product.tax_percentage / 100)

// Add item to order
order_item = INSERT INTO order_items (
    order_id, product_id, variant_id, quantity,
    unit_price, variant_price, tax_percentage, line_total, notes
)

// Update order totals
UPDATE orders SET
    subtotal = subtotal + line_total,
    tax_amount = tax_amount + tax_amount,
    total_amount = subtotal + tax_amount
WHERE id = order_id

RETURN response with order_item

**Pseudocode - Frontend (MenuPage.jsx, CartContext.jsx)**
CONTEXT CartContext:
STATE cart = {
order_id: null,
items: [],
subtotal: 0,
tax: 0,
total: 0
}
FUNCTION addToCart(product, variant, quantity):
    // Check if item already in cart
    existing_item = FIND in cart.items WHERE 
                    product_id = product.id AND 
                    variant_id = variant?.id
    
    IF existing_item:
        existing_item.quantity += quantity
    ELSE:
        cart.items.PUSH({
            product_id: product.id,
            product_name: product.name,
            variant_id: variant?.id,
            variant_name: variant?.attribute_value,
            quantity: quantity,
            unit_price: product.price,
            variant_price: variant?.extra_price || 0
        })
    
    // Recalculate totals
    recalculateCart()
    
    // Persist to backend
    AWAIT orderService.addOrderItem(cart.order_id, item_data)

FUNCTION recalculateCart():
    subtotal = 0
    tax = 0
    
    FOR EACH item IN cart.items:
        item_total = (item.unit_price + item.variant_price) * item.quantity
        subtotal += item_total
    
    tax = subtotal * 0.05 // Assuming 5% tax
    total = subtotal + tax
    
    SET cart.subtotal = subtotal
    SET cart.tax = tax
    SET cart.total = total
COMPONENT MenuPage:
products = AWAIT productService.getAllProducts()
categories = GROUP products BY category_name
FUNCTION handleAddToCart(product, variant, quantity):
    cartContext.addToCart(product, variant, quantity)
    SHOW toast "Added to cart"

RENDER:
    FOR EACH category IN categories:
        SHOW category heading
        FOR EACH product IN category.products:
            SHOW ProductCard with:
                - product image
                - product name
                - price
                - variant selector (if variants exist)
                - quantity selector
                - add to cart button

### **4. Payment Processing**

**Pseudocode - Backend (paymentController.js)**
FUNCTION processPayment(request, response):
GET order_id, payment_method_id, amount FROM request.body
// Verify order
order = SELECT FROM orders WHERE id = order_id

IF order.total_amount != amount:
    RETURN error "Amount mismatch"

// Get payment method details
payment_method = SELECT FROM payment_methods WHERE id = payment_method_id

// Create payment record
payment = INSERT INTO payments (
    order_id,
    session_id: get active session for current user,
    payment_method_id,
    amount,
    status: "pending"
)

// Handle different payment methods
IF payment_method.name is "cash":
    // Mark as completed immediately
    UPDATE payments SET status = "completed", paid_at = NOW()
    WHERE id = payment.id
    
ELSE IF payment_method.name is "upi_qr":
    // Generate QR code
    qr_data = GENERATE QR with UPI string:
              "upi://pay?pa={upi_id}&pn=RestaurantName&am={amount}&tn=Order{order_number}"
    
    RETURN response with {payment_id, qr_code: qr_data, status: "pending"}
    
ELSE IF payment_method.name is "netbanking" OR "card":
    // Return payment gateway mock URL (for hackathon)
    payment_url = "https://mock-payment-gateway.com/pay?ref=" + payment.id
    RETURN response with {payment_id, payment_url, status: "pending"}

// Update order status
UPDATE orders SET status = "paid", paid_at = NOW()
WHERE id = order_id

// Update table status
UPDATE tables SET status = "available"
WHERE id = order.table_id

// Emit socket event for customer display
SOCKET.emit("payment_completed", {order_id, payment_id})

RETURN response with payment
FUNCTION verifyPayment(request, response):
GET payment_id FROM request.params
payment = SELECT FROM payments WHERE id = payment_id

// Mock verification (for hackathon, simulate success)
UPDATE payments SET status = "completed", paid_at = NOW()
WHERE id = payment_id

RETURN response with {verified: true, payment}

        })

    ELSE IF selectedMethod.name is "upi_qr":

            order_id: order.id,
            payment_method_id: selectedMethod.id,

        })
        
        // Open payment URL in new window

        // Poll for payment verification

    SET loading = false

RENDER:

        IF selectedMethod is UPI QR:

            ELSE:
                SHOW "Generate QR" button

            SHOW "Pay Now" button

### **5. Kitchen Display System**

**Pseudocode - Backend (kitchenController.js, Socket Handler)**
FUNCTION getKitchenOrders(request, response):
kitchen_orders = SELECT ko.*, o.order_number, t.table_number
FROM kitchen_orders ko
JOIN orders o ON ko.order_id = o.id
LEFT JOIN tables t ON o.table_id = t.id
WHERE ko.stage IN ('to_cook', 'preparing', 'completed')
ORDER BY ko.received_at ASC
RETURN response with kitchen_orders
FUNCTION updateOrderStage(request, response):
GET order_id, new_stage FROM request.body
UPDATE kitchen_orders SET
    stage = new_stage,
    updated_at = NOW(),
    started_at = CASE WHEN new_stage = 'preparing' THEN NOW() ELSE started_at END,
    completed_at = CASE WHEN new_stage = 'completed' THEN NOW() ELSE completed_at END
WHERE order_id = order_id

// Update main order status
UPDATE orders SET status = new_stage
WHERE id = order_id

// Emit socket event
SOCKET.to('kitchen').emit('order_stage_updated', {order_id, new_stage})
SOCKET.to('customer_' + order.customer_id).emit('order_status_updated', {order_id, new_stage})

RETURN response with updated kitchen_order
SOCKET HANDLER - When order sent to kitchen:
ON EVENT "send_to_kitchen":
GET order_id FROM event_data
    order = SELECT FROM orders WHERE id = order_id
    order_items = SELECT oi.*, p.name, p.category_id
                  FROM order_items oi
                  JOIN products p ON oi.product_id = p.id
                  WHERE oi.order_id = order_id
    
    // Only send items from categories marked to send to kitchen
    kitchen_items = FILTER order_items WHERE category.send_to_kitchen = true
    
    kitchen_order = INSERT INTO kitchen_orders (
        order_id,

FUNCTION getAllOrdersForCashier(request, response):
GET session_id FROM request (current active session)
GET filters FROM request.query (status, table_id, date_range)
query = BUILD query:
    SELECT o.*, 
           t.table_number, 
           t.floor_id,
           f.name as floor_name,
           u.full_name as customer_name,
           COUNT(oi.id) as items_count
    FROM orders o
    LEFT JOIN tables t ON o.table_id = t.id
    LEFT JOIN floors f ON t.floor_id = f.id
    LEFT JOIN users u ON o.customer_id = u.id
    LEFT JOIN order_items oi ON o.id = oi.order_id
    WHERE o.session_id = session_id

IF filters.status:
    query += AND o.status = filters.status

IF filters.table_id:
    query += AND o.table_id = filters.table_id

IF filters.date_range:
    query += AND o.created_at BETWEEN filters.start_date AND filters.end_date

query += GROUP BY o.id, t.table_number, f.name, u.full_name
query += ORDER BY o.created_at DESC

orders = EXECUTE query

RETURN response with orders

FUNCTION getSalesReport(request, response):
GET filters FROM request.query:
- period (today, week, month, custom)
- session_id
- responsible (user_id)
- product_id
- start_date
- end_date
// Build date range
IF period is "today":
    date_range = {start: TODAY 00:00, end: TODAY 23:59}
ELSE IF period is "week":
    date_range = {start: 7 days ago, end: NOW}
ELSE IF period is "custom":
    date_range = {start: filters.start_date, end: filters.end_date}

// Main sales query
sales_data = SELECT 
                COUNT(o.id) as total_orders,
                SUM(o.total_amount) as total_revenue,
                SUM(o.tax_amount) as total_tax,
                SUM(o.discount_amount) as total_discounts,
                AVG(o.total_amount) as average_order_value
             FROM orders o
             WHERE o.status = 'completed'
             AND o.created_at BETWEEN date_range.start AND date_range.end

IF filters.session_id:
    sales_data += AND o.session_id = filters.session_id

IF filters.responsible:
    sales_data += AND (o.user_id = filters.responsible OR o.cashier_id = filters.responsible)

// Payment method breakdown
payment_breakdown = SELECT 
                       pm.display_name,
                       COUNT(p.id) as transaction_count,
                       SUM(p.amount) as total_amount
                    FROM payments p
                    JOIN payment_methods pm ON p.payment_method_id = pm.id
                    WHERE p.status = 'completed'
                    AND p.created_at BETWEEN date_range.start AND date_range.end
                    GROUP BY pm.display_name

// Hourly sales trend
hourly_trend = SELECT 
                  EXTRACT(HOUR FROM created_at) as hour,
                  COUNT(id) as orders_count,
                  SUM(total_amount) as revenue
               FROM orders
               WHERE status = 'completed'
               AND created_at BETWEEN date_range.start AND date_range.end
               GROUP BY hour
               ORDER BY hour

// Product-specific filtering
IF filters.product_id:
    product_sales = SELECT 
                       p.name,
                       SUM(oi.quantity) as units_sold,
                       SUM(oi.line_total) as revenue
                    FROM order_items oi
                    JOIN products p ON oi.product_id = p.id
                    JOIN orders o ON oi.order_id = o.id
                    WHERE o.status = 'completed'
                    AND oi.product_id = filters.product_id
                    AND o.created_at BETWEEN date_range.start AND date_range.end

report = {
    summary: sales_data,
    payment_breakdown,
    hourly_trend,
    product_sales (if filtered)
}

RETURN response with report
FUNCTION getProductReport(request, response):
GET date_range FROM request
product_stats = SELECT 
                   p.id,
                   p.name,
                   c.name as category,
                   SUM(oi.quantity) as units_sold,
                   SUM(oi.line_total) as revenue,
                   COUNT(DISTINCT oi.order_id) as order_count,
                   AVG(oi.line_total / oi.quantity) as avg_price
                FROM order_items oi
                JOIN products p ON oi.product_id = p.id
                JOIN product_categories c ON p.category_id = c.id
                JOIN orders o ON oi.order_id = o.id
                WHERE o.status = 'completed'
                AND o.created_at BETWEEN date_range.start AND date_range.end
                GROUP BY p.id, p.name, c.name
                ORDER BY revenue DESC

RETURN response with product_stats

FUNCTION useRealtimeSubscription(tableName, filter, callback):
useEffect:
channel = supabase
.channel(${tableName}_realtime)
.on('postgres_changes', {
event: '*',
schema: 'public',
table: tableName,
filter: filter
}, (payload) => {
callback(payload)
})
.subscribe()
    RETURN cleanup function:
        supabase.removeChannel(channel)

dependencies: [tableName, filter]

### Database Tables (Supabase PostgreSQL)

The following tables are implemented in Supabase PostgreSQL
and defined in `schema.sql`. These tables are REQUIRED
for backend and frontend functionality.

Core Tables:
- users
- floors
- tables
- product_categories
- products
- product_variants
- orders
- order_items
- payments
- pos_sessions
- kitchen_orders
- feedback
- payment_methods
- self_order_tokens
- reports_cache

Notes:
- All tables use UUID primary keys
- Monetary fields use DECIMAL / NUMERIC
- Foreign keys enforce relational integrity
- Timestamps are present on all transactional tables

`schema.sql` is the single source of truth for table definitions.
