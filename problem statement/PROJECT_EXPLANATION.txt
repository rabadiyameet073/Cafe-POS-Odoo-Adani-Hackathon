1. WHAT IS THIS PROJECT?
========================

Odoo Cafe POS is a full-stack Restaurant Point of Sale (POS) system. It is a
web application that allows a cafe/restaurant to manage everything digitally -
from customers ordering food from their table using a QR code to the kitchen
receiving orders in real-time, the cashier processing payments, and the admin
managing the entire operation from a dashboard.

Think of it like Zomato's dine-in ordering system + a full restaurant
management backend - all in one web app.


2. WHO USES THIS SYSTEM? (4 ROLES)
===================================

The system has 4 types of users, each with their own dashboard and features:

  a) CUSTOMER
     - Scans QR code at their table
     - Selects their floor and table
     - Browses the menu with categories (Soda, Pizza, Burger, Coffee, etc.)
     - Adds items to cart
     - Places order
     - Chooses payment method (Cash / UPI QR / Net Banking)
     - Tracks order status in real-time (Placed → Preparing → Ready → Served)
     - Submits feedback (food quality, service speed, ambience ratings)

  b) CASHIER
     - Opens POS session
     - Views all incoming customer orders
     - Processes walk-in orders manually
     - Confirms cash payments
     - Manages table availability
     - Views daily sales dashboard
     - Closes session at end of shift

  c) KITCHEN STAFF
     - Views Kitchen Display System (KDS) - a screen showing all pending orders
     - Updates order status: To Cook → Preparing → Ready → Served
     - Marks individual items as completed
     - Gets real-time notifications for new orders

  d) ADMIN
     - Full system control
     - Dashboard with live stats (total tables, occupied, revenue, orders)
     - Product Management: Add/edit/delete menu items, set prices, categories
     - Floor Management: Create floors (Ground Floor, First Floor, Outdoor, etc.)
     - Table Management: Add/edit/delete tables, assign to floors, monitor status
     - Payment Monitoring: View all transactions (Cash, UPI), revenue tracking
     - Reports & Analytics: Sales reports, product reports, payment reports
     - Settings: Cafe name, tax rate, timer duration, UPI ID, preferences

3. HOW DOES THE CUSTOMER FLOW WORK?
====================================

Step 1: Customer sits at a table and scans the QR code
Step 2: They are taken to the web app → Floor/Table Selection page
Step 3: They browse the menu (categorized: Soda, Coffee, Pizza, Burger, etc.)
Step 4: They add items to their cart
Step 5: They proceed to checkout
Step 6: They choose payment method:
        - Cash: "Go to the cashier and pay. The cashier will confirm."
        - UPI: QR code is generated with the exact amount
        - Net Banking: Online payment flow
Step 7: Order goes to the kitchen automatically
Step 8: They track their order live: Placed → Preparing → Ready → Served
Step 9: After the meal, they can submit feedback with star ratings
Step 10: After 39 minutes of inactivity, the table auto-releases


4. TECHNOLOGY STACK (WHAT IS BUILT WITH)
=========================================

FRONTEND (What the user sees):
  - React.js 18        → JavaScript library for building the UI
  - Vite 5             → Fast build tool and dev server (runs on port 5173)
  - React Router v6    → Page navigation (login, dashboard, menu, etc.)
  - Tailwind CSS 3     → Styling framework (dark theme, responsive design)

  - Socket.IO Client   → Real-time communication (live order updates)
  - Supabase JS Client → Direct database access from frontend

  - Node.js 18+        → JavaScript runtime for server
  - Express.js 4       → Web framework (runs on port 3000)
  - PostgreSQL         → Database (hosted on Supabase cloud)
  - JWT                → Authentication tokens (login sessions)

  - Socket.IO          → Real-time events (kitchen notifications)

  - CORS               → Cross-origin request handling

DATABASE:
  - Supabase (PostgreSQL) → Cloud-hosted database
  - URL: https://smxqcotsqhiofecfzykg.supabase.co
  - 40+ database tables
  - Real-time subscriptions (live data updates without page refresh)
  - Row-level security

DEPLOYMENT:

  - Frontend: Static site deployment
  - Backend: Serverless functions


5. DATABASE STRUCTURE (WHAT DATA IS STORED)
=============================================

The database has 40+ tables. Here are the most important ones:

  users              → All user accounts (name, email, password hash, role)
  products           → Menu items (name, price, description, image, category)
  product_categories → Categories like Soda, Pizza, Burger, Coffee
  orders             → Customer orders (table, items, total, status)
  order_items        → Individual items in each order
  payments           → Payment records (amount, method, status, timestamps)
  tables             → Restaurant tables (number, seats, status, floor)
  floors             → Floor organization (Ground Floor, First Floor, etc.)
  cart               → Shopping cart per customer session
  cart_items          → Items in the cart
  table_sessions     → QR token sessions (links customer to table)
  kitchen_orders     → Orders as seen on the kitchen display
  customer_feedback  → Ratings and comments from customers

Key Features of the Database:
  - Automatic triggers: When payment is confirmed, order status updates
  - QR token generation: Each table session gets a unique token
  - 39-minute auto-release timer: Tables free up automatically
  - Audit logs: All admin actions are logged
  - Status history: Every order status change is tracked

8. DUAL DATA STRATEGY
======================

The frontend uses TWO ways to access data:

  1. BACKEND API (through Express server)
     - REST API calls via axios
     - Routes: /api/products, /api/orders, etc.
     - Requires backend server to be running
     - Used for complex operations (payments, auth)

  2. SUPABASE DIRECT (through Supabase JS client)
     - Direct database queries from the frontend
     - Always available (cloud-hosted)
     - Used as PRIMARY source for admin pages
     - Real-time subscriptions for live updates

  WHY BOTH?
  - The backend server may not always be running (especially in serverless)
  - Supabase direct gives instant access to data without backend
  - Admin pages use "Supabase-first, backend-fallback" pattern
  - This ensures the app works even if only the frontend is deployed


9. REAL-TIME FEATURES
======================

The app has live, real-time updates without page refresh:

  a) Socket.IO (Backend → Frontend):
     - New order notification to kitchen
     - Payment confirmation to customer
     - Table status change broadcast

  b) Supabase Realtime Subscriptions:
     - Admin dashboard auto-refreshes when data changes
     - Tables page shows live status changes
     - Payment monitor updates instantly
     - Order tracking page shows live progress

  Example: When a customer places an order:
    1. Order is saved to database
    2. Supabase sends real-time event
    3. Kitchen display instantly shows the new order
    4. Admin dashboard updates the order count
    5. All of this happens WITHOUT anyone refreshing the page


10. SECURITY FEATURES
======================

  - JWT Authentication: Secure token-based login (expires in 7 days)
  - Password Hashing: bcryptjs with salt rounds (never stored in plain text)
  - Role-Based Access: Admin, Cashier, Kitchen, Customer - each has different
    permissions enforced at both frontend (ProtectedRoute) and backend
    (roleCheckMiddleware)
  - Helmet: Security headers (XSS protection, content-type sniffing prevention)
  - CORS: Only allowed origins can make API calls
  - Input Validation: All user inputs validated before processing
  - Audit Logging: Admin actions are logged for accountability
  - SQL Injection Prevention: Supabase parameterized queries

12. HOW TO RUN THE PROJECT
============================

Prerequisites:
  - Node.js 18 or higher installed
  - npm (comes with Node.js)
  - A Supabase account (database is already configured in the cloud)

Step 1: Install Dependencies

  # Install backend dependencies
  cd backend
  npm install

  # Install frontend dependencies
  cd ../frontend
  npm install

Step 2: Start the Backend Server

  cd backend
  npm start
  # Server starts on http://localhost:3000

Step 3: Start the Frontend Dev Server

  cd frontend
  npm run dev
  # App opens at http://localhost:5173

Step 4: Open in Browser

  http://localhost:5173

  Login with any of these accounts (password: demo123):
    - admin@demo.com     (Admin Dashboard)
    - cashier@demo.com   (Cashier POS)
    - kitchen@demo.com   (Kitchen Display)
    - customer@demo.com  (Customer Ordering)

Note: The frontend can work WITHOUT the backend running because it uses
Supabase direct queries as the primary data source. The backend is needed
for authentication, complex operations, and Socket.IO real-time events.
